# 桌宠形象工坊

把"一张概念图"变成"一套能立刻换上的桌宠动画资产"。全程 5 步，不要跳步。

## 输入

- 用户的**角色概念图**（必须有；没有就先帮用户生成/设计一张正面站姿概念图并请其确认，再开工）。
- 角色包信息：英文 id（小写字母/数字/连字符，如 `lava-pup`）、中文显示名、作者名（可留空）。
- CinderWing 仓库根目录（默认 `C:\git-repo\pet`；不确定就问用户）。下文记作 `<REPO>`。

## 硬约束（踩过几个月坑总结，任何一条不满足都会返工）

1. **9 套动作一套不能少**：idle、blink、tap1、tap2、tap3、drag、happy、talk、scratch。
   动作语义、帧数、节奏见 `references/animation-brief.md`，开工前必须读。
2. **背景统一用纯色青蓝幕布 RGB(0,170,200)**；禁止绿色（溢色穿身）、禁止白色（高光被抠掉）、
   禁止渐变/地面/投影/文字/水印。
3. **每排最多 3 格**，每格正方形、角色居中、全身入镜，翅膀/角/尾巴/手臂四周留 ≥8% 空白，
   任何部位不许贴边出画；条图长边 ≤4000px，单格 ≥1024px。
4. 同一套内角色大小、站位、角度、光照必须完全一致，只有动作在变。
5. 所有条图必须**以用户的概念图为形象锚点**用图生图（image_edit）生成，只变姿势/表情，
   不准换物种、换配色、换头身比。每张图独立完整描述，禁止"同上"。

## 流程

### 1. 准备环境与目录

- 确认 `<REPO>` 下有 `.venv`（没有就指导用户：`python -m venv .venv` 后
  `pip install -r requirements.txt`）。
- 新建工作目录（用户的临时目录或 `<REPO>\\assets\\packs_src\\<id>`），其下建 `sheets/`。
- 抠图模型目录 `<REPO>\\tools\\.u2net`；运行命令时设
  `U2NET_HOME=<REPO>\\tools\\.u2net`（模型不存在会自动下载，约 176MB，属正常）。

### 2. 逐套生成条图

- 先读 `references/animation-brief.md`，按其中每套动作的格数与动作分解写 prompt。
- 一次图生图调用只出**一张条图**（同一套动作；超过 3 格拆多张，如 `tap1_a/b/c`）。
- 生成后**立刻逐张目检**：青蓝底？肢体全在画内？同套站位一致？不合格当场重生，不要攒到最后。
- 把确认可用的原图下载保存为 `sheets/<动作名>.png`（多张时 `tap1_a.png`、`tap1_b.png`…）。

### 3. 写 sheets.json

按 `templates/sheets.json` 写 `sheets/sheets.json`，声明每张图的动作、格数、行数与锚点。
文件名用 `<动作>_<格数>.png`（如 `idle_8.png`）时可省略，但显式 sheets.json 最稳。

### 4. 构建角色包

```powershell
$env:U2NET_HOME="<REPO>\tools\.u2net"
<REPO>\.venv\Scripts\python.exe <REPO>\tools\pack_build.py `
  "<工作目录>\sheets" --id <包id> --name "<显示名>" --author "<作者>"
```

脚本会：逐格 rembg/u2net 语义抠像（免疫幕布溢色，身上不会出现白块）→
连通区清理 → 裁边对齐到 256×256、脚对齐 → 输出到宠物形象文件夹 `packs/<id>/`
→ 生成品红底质检图 `packs/qa_<id>.png`。
包结构与字段见 `references/pack-spec.md`。

### 5. 品红底质检与交付（关键，禁止用白底检查）

- 打开 `qa_<id>.png`（饱和品红 200,30,160 底）逐帧检查，清单见
  `references/pack-spec.md` 的 QA 部分。
- 重点：身体内部不能有透明/白色洞、每帧两只翅膀（或该角色的对应肢体）完整、
  火焰等特效不能出现在错误位置、没有混入邻格内容。
- 哪一帧不合格就只重做那一套条图，然后重跑 pack_build（会覆盖）。
- 全部合格后告诉用户：右键宠物 →「更换形象」→ 选择新形象；若菜单里没出现，
  点一次「打开形象文件夹」确认包目录正确，再重新打开菜单。

## 边界

- 只生成美术资产并调用本地脚本，不修改 app 源码。
- 角色包缺少某几套动作时程序会自动回退默认形象，允许分批交付，但要明确告知用户缺哪几套。
- 涉及受版权保护的角色（如知名游戏 IP）时提醒用户：生成的包仅限个人自用，不要公开分发。
