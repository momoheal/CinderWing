# M4 讲解：小龙怎么变成"双击就能跑、开机自己来"的正式软件？

> 版本：v1.0.0（M4）。　对应代码：`app/paths.py`、`app/main.py`、`pet.spec`、`tools/build_exe.bat`、`tools/post_build.py`、`tools/installer/`
> 阅读对象：零基础的你。看完你能讲清楚：*为什么 Python 写的程序可以打包成 exe？打包后为什么图片和日志会"找不到"？开机自启是怎么实现的？*

---

## 一、M4 要解决什么问题？

M0～M3 做完后，小龙功能完整了，但它有个"学院派"的毛病：**只能在你这台装了 Python 的电脑上、用命令行启动**。
你每次要双击 `启动宠物.bat`，背后其实是 `.venv` 里的 Python 在一行行解释代码。这意味着：

- 换台电脑（哪怕是你自己的电脑重装系统后），要先装 Python、PySide6、一堆依赖；
- 没有"程序图标"，不能开机自启，不像一个真正的软件；
- 黑窗口、venv 文件夹露在外面，很容易误删。

M4 就做两件事：

1. **打包**：把 Python 解释器、PySide6、我们的代码、52 帧动画、音效全部收进一个文件夹，
   里面有一个 `小死亡之翼桌宠.exe`，**双击就跑，目标电脑不需要装 Python**。
2. **驻留**：提供"开机自启-安装.bat"，双击一次，以后开机小龙自己出现；不想要了双击"卸载"即可。

至此 M0～M4 全部完成，版本号从 v0.10.0 升到 **v1.0.0**——这是第一个"正式版"。

## 二、白话原理：打包到底在打什么？

Python 是**解释型语言**：`.py` 文件本身不是机器能直接执行的程序，运行时需要一个
`python.exe` 帮你逐行翻译。所谓"打包成 exe"，不是把 Python 变成 C++ 那种真正的 exe，
而是把**三样东西捆在一起**：

```
小死亡之翼桌宠.exe          ← 一个小启动器（bootloader）
_internal\                  ← 真正的"家当"都在这
  ├─ python313.dll          ← Python 解释器本体
  ├─ PySide6\               ← Qt 界面库（含 Qt6Multimedia.dll 等）
  ├─ ccl_chromium_reader\   ← 读豆包工作数据库的库
  ├─ assets\frames\         ← 52 帧小龙动画
  ├─ assets\sfx\            ← 5 个音效
  └─ 你的 app\ 代码（编译成 .pyc 放在归档里）
```

双击 exe 时，启动器在内存里"变出"一个 Python 环境，然后从归档里加载 `app/main.py` 运行。
对小龙自己来说，它感觉不到区别；但对 Windows 来说，这就是一个普通的原生程序。

我们用的打包工具叫 **PyInstaller**，它有两种常见形态：

| 形态 | 产物 | 优点 | 缺点 |
|---|---|---|---|
| onefile（单文件） | 只有一个 exe | 好拷贝 | 每次运行先把自己解压到临时目录，启动慢、被杀软误报概率高 |
| **onedir（一个文件夹，我们选这个）** | exe + `_internal` 文件夹 | 启动快、稳定、好排查 | 必须整个文件夹一起拷 |

桌宠要开机自启、天天跑，启动速度和稳定性最重要，所以选 **onedir**。
记住：**不能只把 exe 单独拿走**，动画和音效都在旁边的 `_internal` 里。

## 三、打包后最大的坑：路径！路径！路径！

这是 M4 最核心的知识点，也是新手打包 90% 翻车的地方。

### 1. 开发时我们怎么找文件

代码里以前是这样定位动画目录的：

```python
ROOT = os.path.join(os.path.dirname(os.path.dirname(__file__)), "assets", "frames")
```

意思是"从当前这个 .py 文件往上两级，再进 assets/frames"。开发时文件结构是固定的，
没问题。

### 2. 打包后 `__file__` 变了

打包后，代码不是以 `.py` 文件躺在硬盘上，而是被塞进归档、运行时**解压到一个临时/内部目录**，
`__file__` 指向的位置完全不同。更麻烦的是，有两类文件的"诉求"是矛盾的：

- **只读文件**（帧图、音效）：跟着安装包走，在 `_internal\assets\` 里；
- **可写文件**（日志 `pet.log`、位置记忆 `config.json`）：程序运行时要改写它们。
  Windows 下程序装在 `Program Files` 或别人发来的文件夹里时，程序目录**可能没有写权限**；
  而且软件一升级，旧目录被整个替换，你的位置记忆就没了。

Windows 的规矩是：**只读资源跟程序走，可写数据放进当前用户的 AppData 目录**。
几乎所有正规软件都这么干（你可以去 `C:\Users\你的用户名\AppData\Roaming\` 看看，
微信、QQ、各种软件都在这存数据）。

### 3. 我们的解法：一个统一的路径管家 `app/paths.py`

新增的 `paths.py` 是全项目唯一负责"东西在哪"的模块，核心就两个判断：

```python
def is_frozen():
    return getattr(sys, "frozen", False)   # PyInstaller 打包后会留下这个标记
```

- **只读资源** `asset_path('frames')`：
  - 开发态 → 项目根 `assets\frames`
  - 打包态 → PyInstaller 解包目录（`sys._MEIPASS`）下的 `assets\frames`
- **可写数据** `data_dir()`：
  - 开发态 → 还是项目根 `assets`（保持你开发时的老习惯，日志照旧）
  - 打包态 → **`%APPDATA%\GeoHarbourPet\`**，没有就自动创建

然后把 `main.py`、`task_source.py`、`sfx.py`、`sprite_anim.py`、`pet_window.py`
里所有写死的路径全部改成问 `paths` 要。这样一套代码在两种环境下都能找到自己的东西。

> 你以后要验证打包版的行为，记住两个位置：
> - 看日志/位置：`%APPDATA%\GeoHarbourPet\pet.log`（在资源管理器地址栏直接粘
>   `%APPDATA%\GeoHarbourPet` 就能打开）
> - 看程序：`dist\小死亡之翼桌宠\`

### 4. 还有一个细节：config.json 不打包

`pet.spec` 里只打包了 `frames` 和 `sfx`，**故意不打包 `config.json`**。
它记录的是"小龙上次被你拖到屏幕哪里了"，属于可写数据，第一次运行时在 AppData 里自然生成。
如果把开发机上的 config.json 打进包里，每个用户第一次打开小龙都会出现在*你*电脑的位置上。

## 四、`pet.spec`：打包的施工图纸

PyInstaller 可以用一长串命令行参数，但我们把所有配置写进了 **`pet.spec`**（Python 语法的配置文件），
可复现、好 review。关键几段：

```python
datas = [
    ('assets/frames', 'assets/frames'),   # 把帧图原样收进包
    ('assets/sfx', 'assets/sfx'),         # 音效
]
hiddenimports = ['PySide6.QtMultimedia']  # 音效模块，显式声明保险

d, b, h = collect_all('ccl_chromium_reader')  # M2 的数据库解析库，整包收集
```

两个值得讲的点：

1. **为什么要 `collect_all('ccl_chromium_reader')`？**
   PyInstaller 靠静态扫描找依赖，但 `ccl_chromium_reader` 是在函数内部**懒加载**的
   （用到时才 import），扫描器看不见，不手动收集的话，打包版一到读任务就崩。
2. **`excludes` 里为什么排掉 rembg、onnxruntime？**
   这两个是 M1 美术流水线用的 AI 抠图库（合计几百 MB），**运行时的小龙根本不需要**
   （帧图早就抠好成 PNG 了）。排掉之后整个包只有约 137 MB，否则会膨胀到 500 MB 以上。

其余配置：

- `console=False`：不弹黑窗口（桌宠要安静）；
- `icon='assets/app.ico'`：exe 和任务栏的图标，是用 `tools/make_icon.py` 从核心形象图
  生成的多尺寸 ico（16/24/32/48/64/128/256）；
- `name='小死亡之翼桌宠'`：exe 和成品文件夹的中文名。

构建命令封在 **`tools/build_exe.bat`**（ASCII + CRLF，还记得 M0 的教训吗），
打完还会自动跑 `tools/post_build.py`，把开机自启脚本和使用说明复制进成品文件夹。

## 五、真实排错故事：窗口版"静默死亡"怎么破？

第一次打包非常顺利，双击 exe——进程在任务管理器里躺着，**没有窗口、没有日志、没有报错**，
像一具"僵尸"。这就是 `console=False` 的代价：程序在你看不见的地方死了，
错误信息也没人接收。

排查方法（这是个通用套路，值得记住）：

1. **出一个调试包**：复制一份 spec，只改两处——`console=True`、名字改成 `pet_debug`，
   重新打包。这个版本双击会带一个黑色控制台，Python 的报错会直接打在上面。
2. 运行调试版，立刻看到真凶：

```
File "main.py", line 20, in setup_logging
NameError: name 'os' is not defined
```

原来是 M4 改路径时，我把 `main.py` 顶部的 `import os` 顺手删掉了，
但下面的日志代码还在用 `os.path.abspath`。开发态的离线测试恰好没 import `app.main`，
所以没暴露；一打包就现形。
3. 补回 `import os` → 重新打包 → 小龙正常出现。调试包使命完成，删除。

**经验**：windowed 程序出问题，不要猜，立刻出 console 版让它把错误吐出来。
另外这也说明：打包后必须真机跑一遍——"构建成功"只代表捆好了，不代表能跑。
我们真机验证了：日志写到 AppData、事件循环正常、任务轮询无报错、
Qt 多媒体 DLL 和两个后端插件（ffmpeg / windows media）都在、抓屏小龙显示正常。

## 六、开机自启：启动文件夹里的"快捷方式"

### 1. 原理

Windows 给每个用户留了一个**启动文件夹**：

```
C:\Users\<用户名>\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup
```

登录 Windows 时，系统会自动运行这个文件夹里的每个快捷方式（.lnk）。
我们要做的，就是放一个指向 exe 的快捷方式进去。它的好处：

- **不需要管理员权限**（另一种方案是写注册表 `HKCU\...\Run`，效果类似但更"硬核"）；
- 不想要了，删掉快捷方式即可，干净可逆，用户自己也能在
  "任务管理器 → 启动"页里看到并禁用它。

### 2. 为什么是脚本而不是手动教你建？

快捷方式里除了"目标程序"，还要设置"起始位置"（否则程序找不到同目录的 `_internal`）。
手动建容易漏。所以成品文件夹里有：

| 文件 | 作用 |
|---|---|
| 开机自启-安装.bat | 双击 → 调用 `install_autostart.ps1` 生成快捷方式 |
| 开机自启-卸载.bat | 双击 → 删除快捷方式（程序本体保留） |
| install_autostart.ps1 / uninstall_autostart.ps1 | 真正干活的 PowerShell 脚本 |
| 使用说明.txt | 启动、退出、音效、自启、日志位置的说明 |

bat 只负责调 PowerShell（`.bat` 内容保持纯 ASCII，中文逻辑放在 UTF-8 带 BOM 的 `.ps1` 里，
这是 Windows 脚本编码的老规矩，`tools/post_build.py` 会自动把编码处理对）。

快捷方式关键三行：

```powershell
$s.TargetPath = $exe          # 指向 小死亡之翼桌宠.exe
$s.WorkingDirectory = $dir    # 起始位置 = exe 所在文件夹
$s.WindowStyle = 7            # 最小化
```

### 3. 双开怎么办？——单实例互斥量

开机自启后，如果你又手滑双击了 exe，会不会出现两条龙？不会。M0 就埋了
**单实例互斥量**（`Global\GeoHarbourPet_SingleInstance_v1`）：第二个实例启动时发现
"已经有一条龙在跑了"，会在日志写一句"已有实例运行，退出"然后自己结束。
我们真机验证过：装好自启后再点快捷方式，进程数始终是 1。

> 注意：因为有互斥量，**开发态（启动宠物.bat）和打包版不要同时跑**，后启动的那个会静默退出。

## 七、你现在拥有什么、日常怎么用

**成品文件夹** `dist\小死亡之翼桌宠\`（约 137 MB，绿色软件，整个文件夹可拷贝/压缩备份）：

- 双击 `小死亡之翼桌宠.exe` → 小龙出现；
- 右键托盘小龙图标 → 显示/隐藏、测试通知、模拟全流程、音效开关、退出；
- 双击 `开机自启-安装.bat` → 以后开机自动出现（已为你安装并验证）；
- 日志和位置在 `%APPDATA%\GeoHarbourPet\`。

**以后改了代码怎么重新打包？**

```
双击 tools\build_exe.bat
```

它会自动清理旧构建、重新打包、复制自启脚本。自启快捷方式指向的是固定路径
`dist\小死亡之翼桌宠\小死亡之翼桌宠.exe`，所以重新打包后**不用重新安装自启**；
但如果你把文件夹挪走了，要重新双击"安装"。

## 八、小作业（不用交，自己动手会更有感觉）

1. **认路径**：打开 `%APPDATA%\GeoHarbourPet\`，把小龙拖到屏幕另一个位置后退出，
   打开 `config.json` 看看坐标有没有变；再把这个文件删掉重启，观察小龙是不是回到了
   默认的右下角。
2. **看自启**：按 `Win+R`，输入 `shell:startup` 回车，亲眼找到那个"小死亡之翼桌宠"快捷方式；
   右键看属性，确认"目标"和"起始位置"。然后双击"开机自启-卸载.bat"，刷新文件夹看它消失，
   再双击"安装"恢复。
3. **读图纸**：打开 `pet.spec`，对照第四节，找出哪一行决定了"没有黑窗口"、
   哪一行决定了 exe 的图标、哪几行把动画装进包。
4. **思考题**：如果将来你想让小龙在别的同事电脑上也能跑，直接把整个
   `小死亡之翼桌宠` 文件夹拷过去就行——但 M2 的任务通知功能依赖什么本机条件？
   （提示：它读的是谁电脑上的 IndexedDB？路径里写死了什么？）想明白这个，
   你就知道为什么这个项目"严格自用"了。
