# M5 讲解：小龙学会了"听你指挥"——右键菜单与决策选项

> 版本：v1.1.0（M5）。　对应代码：`app/pet_window.py`、`app/bubble.py`、`app/tray.py`、`app/task_source.py`、`app/dev_sim.py`
> 阅读对象：零基础的你。看完你能讲清楚：*右键菜单是怎么弹出来的？AI 提问的选项怎么变成可点的按钮？为什么点选项后还要去豆包里再确认一次？*
> 本里程碑还顺手修好了一个"小龙突然听不到任务"的数据源故障（见第六节），这是 v1.1.0 最重要的幕后修复。

---

## 一、M5 要解决什么问题？

M0～M4 做完后，小龙能站在桌面上、能汇报任务、能打包成 exe，但你对它的"控制手段"很少：

- 想让它**临时藏起来**（比如要投屏、要全屏看视频），只能去托盘里找，或者直接退出；
- 想主动逗它，只能用鼠标点；想让它喷火、欢呼、去睡觉，没有"菜单"可以选；
- 最关键的：当 AI（也就是豆包工作里的我）在任务中**抛出选择题让你做决定**时，
  小龙只会说"需要你决策"，你还得自己切到豆包窗口、找到那条消息、读题、点选项。

M5 就做两件事：

1. **右键菜单**：在小龙身上点右键，弹出菜单——任务进度、逗逗它（喷火/扑咬/开心欢呼/去睡觉）、
   音效开关、隐藏宠物、退出。托盘菜单同步升级。
2. **决策气泡里直接出选项**：AI 提问时，小龙的气泡里直接把每一个选项画成按钮，
   点哪个按钮就**跳到豆包工作的对应会话**，你在里面确认发送即可。

## 二、白话原理：右键菜单是怎么弹出来的？

我们的窗口是一个"无边框透明置顶工具窗"（M0 做的），没有系统标题栏，所以菜单要自己接。

Qt 里每个窗口都能收到一个事件叫 `contextMenuEvent`（上下文菜单事件）——
**在窗口里点鼠标右键时，Qt 就会调用这个函数**。我们在 `pet_window.py` 里重写了它：

```python
def contextMenuEvent(self, event):
    menu = QMenu(self)
    menu.setStyleSheet(...)          # 深色皮肤，和气泡一个风格
    menu.addAction("任务进度", ...)  # 每一项是一个 QAction
    play_menu = menu.addMenu("逗逗它")   # 子菜单
    play_menu.addAction("喷火", ...)
    ...
    sound = QAction("音效开关", menu, checkable=True)  # 可勾选项
    sound.setChecked(self.sfx.enabled)
    menu.addAction(sound)
    menu.addAction("隐藏宠物", self.hide)
    menu.addAction("退出", QApplication.instance().quit)
    menu.exec(event.globalPos())     # 在鼠标位置弹出
```

几个知识点：

- **QMenu / QAction**：菜单（QMenu）里装的每一行叫动作（QAction），点动作就触发它绑定的函数。
- **子菜单**：`addMenu("逗逗它")` 返回一个新菜单，往它里面加动作，就变成了"右箭头展开的二级菜单"。
- **checkable（可勾选）动作**：音效开关前面会出现一个 ✓，表示当前是开还是关；
  托盘里的音效开关和它读的是同一个开关（`sfx.enabled`），所以两边永远一致。
- **隐藏 ≠ 退出**：`self.hide()` 只是把窗口藏起来，程序还在托盘里运行，双击托盘图标就回来；
  退出才是真正结束进程。

"逗逗它"里的四个动作走同一个函数 `_manual_play(name)`：先清掉拖拽/睡眠等临时状态，
再像左键互动一样播放对应动画和音效——**复用已有代码，不另写一套**，这是菜单动作可靠的原因。

## 三、决策选项：AI 的提问是怎么变成按钮的？

### 1. 数据从哪来？

豆包工作把每条任务的完整过程写在 IndexedDB（M2 讲过的本地数据库）里。
AI 向人提问时，会插入一种类型号为 **10082** 的内容块 `interaction_ask_block`，
里面的结构（我们通过阅读客户端前端 JS 逆向确认）是：

```
interaction_ask_block
├─ status                # 1 = 等待你回答；2 = 已关闭
└─ questions[]           # 一次可以有多个问题
   ├─ title              # 问题原文
   ├─ type               # 1 单选 / 2 多选 / 3 自由文本
   ├─ options[]          # 选择题的选项
   │   ├─ option_id
   │   └─ label          # 选项文字
   └─ question_capability.allow_text   # 是否允许自己输入一段话
```

M5 在 `task_source.py` 里做了两件事：

- 轮询时一旦发现 **status=1 的 10082 块**，就把问题和选项提取出来，
  规范化成统一的小字典 `ask`，跟着"需要你决策"事件一起送给气泡；
- 任务状态因此进入 **WAITING（等待决策）**，进度条停住、气泡变红。

### 2. 按钮怎么画出来、怎么知道你点了哪个？

M3 的气泡已经是"自己用画笔（QPainter）画出来的无边框窗口"。M5 在 `bubble.py` 里：

- 用圆角矩形把每个选项画成**红边按钮**（悬停时底色加深），自由输入入口画成灰边按钮；
- 画每个按钮的同时，把它的屏幕矩形（QRect）记进 `self._opt_rects` 列表；
- 鼠标移动时检查光标落在哪个矩形里，落在按钮上就变成**小手光标**并重绘高亮；
- 鼠标按下时同样查矩形，命中任何一个选项/自由输入按钮，就发出
  `jump_requested(会话id)` 信号——和 M3"点气泡跳转"是同一条链路。

布局测量（每个按钮多高、气泡多宽）抽成了统一函数 `_collapsed_items()`，
"自动测量尺寸"和"实际绘制"都走它，避免出现"画的位置和点击热区对不上"的问题。

### 3. 为什么点了按钮还要去豆包里再确认一次？（重要事实）

这是 M5 调研后确认的**能力边界**，不是偷懒：

- 豆包工作提交答案走的是它**应用内部的 IM 通信通道**（前端 JS 里的 `submitToServer`，
  需要登录态、会话上下文、消息线程 id），这个通道**不对外部程序开放**；
- 小龙是一个独立的外部程序，**无法替你把答案发出去**——如果假装发了，会造成
  "你以为选了 A，实际豆包那边什么都没收到"的更糟体验。

所以 M5 的设计是：**气泡里看题、选答案 → 自动跳到豆包对应会话（问题卡片就在最新消息处）
→ 你在卡片上点同一个选项、按发送**。只多一下确认，不会找错会话、不会漏题。
气泡底部也用红字写明了这一步："点击选项 → 打开豆包，在里面确认发送"。

另外两个贴心点：

- **决策气泡不会自动消失**（其他气泡 8～12 秒淡出，决策气泡常驻，直到你处理）；
- 没有选项的纯自由文本题，只显示一个"去豆包回答"的灰按钮。

## 四、右键菜单"任务进度"与空状态

菜单第一项"任务进度"和托盘里的"任务进度面板"是同一个功能：展开 M3 的多任务面板，
每个任务一行，带进度条，点行跳转到对应会话。

M5 补了**空状态**：当前一个进行中的任务都没有时，小龙会弹一个小提示
"现在没有进行中的任务，小龙在待命"，而不是点了没反应让人以为坏了。

## 五、你现在能做什么（操作清单）

| 操作 | 效果 |
|---|---|
| 在小龙身上**右键** | 弹出菜单 |
| 菜单 → 任务进度 | 看多任务进度条面板，点行跳会话 |
| 菜单 → 逗逗它 → 喷火/扑咬/开心欢呼/去睡觉 | 立即播放对应动画 |
| 菜单 → 音效开关 | 开关声音（✓ = 开），托盘菜单同步 |
| 菜单 → 隐藏宠物 | 藏起小龙；双击托盘图标恢复 |
| 菜单 → 退出 | 完全退出 |

9 秒处会出现一道带 3 个选项的单选题（开发模拟模式）。

## 六、幕后大事：修复"小龙突然听不到任务"

M5 测试时发现小龙一个真实任务都检测不到了。排查过程（也是很好的学习案例）：

1. **现象**：数据库里 `default-chat-im-protocol-store`（M2 的任务数据源）的最新记录
   全部反序列化失败，113 个历史版本没有一个能读出。
2. **定位**：大任务数据存在数据库旁边的 `.blob` 文件夹里，数据库里只留一个
   "我在第几个 blob 文件、有多少字节"的索引。我们用的第三方库按**编号**找文件，
   但豆包工作在持续运行、blob 文件不断轮换，**快照里新旧索引混排，编号指向了已经
   被换掉的旧文件**，于是解析失败。
3. **修复**（`app/task_source.py`）：
   - 记录信封里除了编号，还写着这份数据的**精确字节数**。编号找不到文件时，
     就按"字节数完全相等"在 blob 目录里兜底匹配（字节数和数据是原子写入的，最可靠）；
   - 每轮快照改用**全新的临时目录**（旧目录里的文件被上一轮读取句柄占用，
     Windows 上删不掉，复用目录会导致拷贝一直报"文件已存在"），读完立即关闭所有句柄；
   - 拷贝顺序改为先 blob 后 leveldb，缩小与运行中客户端的竞态；
   - 顺带认识了新内容块 10063（本地文件引用，不计入工具进度），不再刷未知日志。
4. **验证**：离线回归重新读到 2 个真实进行中任务，打包版真机轮询恢复正常。

**给你的编程课**：和正在运行的程序抢读它的数据库文件，本质是在和"变化"打交道。
不要假设文件布局永远不变；关键数据尽量用**随数据一起写入的信息**（这里是字节数）自证身份，
比用可能过期的旁证（编号表）可靠得多。
