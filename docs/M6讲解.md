# M6 讲解：小龙会"换皮肤"了——角色包系统与形象工坊

> 版本：v1.2.0（M6）。　对应代码：`app/packs.py`、`app/config_store.py`、`app/sprite_anim.py`、`app/skill_import.py`、`app/pet_window.py`、`tools/pack_build.py`、`skills/cinderwing-asset-forge/`
> 阅读对象：零基础的你。看完你能讲清楚：*为什么换个形象不用改代码？一张概念图是怎么变成一套桌宠动画的？技能（Skill）为什么能"一键导入"？*

---

## 一、M6 要解决什么问题？

M0～M5 做完后，小龙的长相是"焊死"在程序里的：52 张帧图放在 `assets/frames/`，
代码直接去那里读。想换一只小狐狸、小史莱姆？做不到。

M6 的目标是让桌宠像游戏皮肤一样**可换装**，而且做新皮肤的过程尽量自动化：

1. **角色包系统**：每只宠物是一个"包"（一个文件夹），内置小龙是其中一个包；
   右键菜单「更换形象」可以在各个包之间切换，选择会被记住。
2. **通用构建工具 `pack_build.py`**：以前抠图切帧的流水线是给小龙手写的，
   现在改造成通用工具——任何角色的 AI 条图丢进去，都能加工成角色包。
3. **形象工坊技能（Skill）**：把"9 套动作怎么画、青蓝底、每排≤3 格……"
   这几个月踩坑换来的规范打包成一个 AI 技能。你在豆包工作里上传一张概念图，
   AI 就按规范生成全套条图、调用构建工具、品红底质检，一条龙产出新形象。

## 二、白话原理：角色包是什么？

### 1. 一个包 = 一个文件夹，自带"身份证"

```
packs/
└── lava-pup/                 # 包 id（英文、唯一）
    ├── pack.json             # 身份证：id、名字、作者、播放速度
    ├── preview.png           # 菜单里看到的缩略图
    └── frames/               # 9 套动作的帧图
        ├── idle/00.png 01.png ...
        ├── blink/ ...
        └── ...（共 9 个动作目录）
```

`pack.json` 长这样：

```json
{
  "id": "lava-pup",
  "name": "熔岩小狗",
  "author": "你的名字",
  "version": 1,
  "fps": {"idle": 2, "blink": 9, "tap1": 9, "tap2": 9,
          "tap3": 7, "drag": 2, "happy": 9, "talk": 8, "scratch": 7}
}
```

程序启动时去"形象文件夹"里**扫描**所有符合这个结构的文件夹，
每个都变成一个 `Pack` 对象（`app/packs.py`）。
这就是"插件化"：加形象 = 加文件夹，不用改一行代码。

### 2. 内置形象也是一个包，而且不能被冒充

内置小龙住在 `assets/frames/`，id 固定为 `cinderwing`。
用户包即使在 pack.json 里写 `"id": "cinderwing"`，扫描时也会被强制改名
（`packs.py` 里的 `cinderwing__from_<文件夹名>` 逻辑），
防止一个坏包把官方形象顶掉。

### 3. 缺动作怎么办？自动回退，不许崩

新包只画了 idle 和 blink 也能用：播放器装载某套动作时，
新包里没有就**回退到内置包的同名动作**（`SpritePlayer.set_pack` 里
`fallback.frames.get(anim)`）。这样朋友给你半成品包，程序也不会白屏。

### 4. 播放器从"读死目录"改成"读包"

M5 以前 `sprite_anim.py` 里写死了帧图根目录。M6 改成：

```python
player = SpritePlayer(pack, fallback=builtin_pack)
player.set_pack(new_pack)   # 换装：停计时器 → 重新装载 9 套帧 → 从 idle 开始
```

这里踩过一个坑：`set_pack` 里会先 `timer.stop()`，所以**计时器必须在
set_pack 之前创建**，否则第一次换装就 AttributeError。这种"初始化顺序"
问题在 GUI 编程里很常见，值得记住。

### 5. 配置统一收口到 config_store

以前窗口位置是直接读写 config.json 的，换装也要写配置，
两处各写各的很容易互相覆盖。M6 新增 `app/config_store.py`：

```python
config_store.get("pack_id", 默认值)
config_store.update("pack_id", "lava-pup")   # 只改这一个键，不动其他内容
```

所有配置读写都走它，窗口位置、当前形象都存在同一个 config.json 里。

## 三、右键菜单怎么换装？

`pet_window.py` 把右键菜单的搭建单独抽成了 `_build_context_menu()`
（顺便让离屏测试也能检查菜单结构）。「更换形象」是一个子菜单：

- 扫描到的每个包生成一个**可勾选菜单项**（QAction + QActionGroup 单选），
  当前形象打勾；
- 分隔线下面两个固定项：「打开形象文件夹」「制作新形象（导入生成技能）…」。

点某个形象 → `_switch_pack(id)`：播放器换包 → 写入配置 → 播一个点击音 →
无论当时在睡觉还是喷火都回到新形象的待机 → 气泡提示"已换上新形象"。

「打开形象文件夹」用 `os.startfile` 打开 packs 目录——
以后你下载了别人的形象包，把文件夹拖进去，重新打开菜单就能看到。

## 四、pack_build.py：把条图变成角色包

它复用了小龙流水线里最成熟的两味"药"（直接 import `build_frames.py`）：

- `ai_cutout()`：rembg/u2net **语义抠像**。这是 M1 阶段最大的经验——
  青蓝幕布（RGB 0,170,200）+ AI 抠像，幕布颜色反射到身上也不会被抠穿，
  身上不会出现白色/透明洞（绿幕会溢色、白底会把高光误抠，都已被否决）。
  抠完还做连通区清理：只保留最大的身体主体，丢掉贴边的碎块和邻格漏进来的火。
- `place()`：透明底裁边 → 等比缩放到 205 高 → 脚对齐贴到 256×256 画布固定位置。
  这保证每套动作、每个角色的站位一致，不会忽大忽小、水平漂移。

用法：

```powershell
$env:U2NET_HOME="C:\git-repo\pet\tools\.u2net"
.venv\Scripts\python.exe tools\pack_build.py sheets文件夹 `
  --id lava-pup --name "熔岩小狗" --author "你的名字"
```

它怎么知道一张条图切几格？三种方式，从稳到省事：

1. `sheets.json` 显式声明（推荐，技能生成时自动写）；
2. 文件名带数字：`happy_3.png` 表示 3 格；
3. 按宽高比猜：每格近似正方形，几格就约等于几比一。

构建完自动产出两样东西：

- **角色包本体**（放进形象文件夹，菜单立刻可见）；
- **品红底质检图 `qa_<id>.png`**：每套动作一行铺在饱和品红
  RGB(200,30,160) 上。为什么不是白底？因为角色身上的浅色高光在白底下
  看不出有没有被误抠，品红底一衬，透明洞、白块、青蓝残边都无处藏身。
  脚本还会对比各帧的不透明像素数，某帧明显"缺肉"或"多东西"时打印警告。

## 五、形象工坊技能：把规范变成 AI 的工作手册

`skills/cinderwing-asset-forge/` 是一个**豆包工作自定义技能**：

```
cinderwing-asset-forge/
├── SKILL.md                    # 主流程：5 步走
├── README.md                   # 给人看的说明
├── references/
│   ├── animation-brief.md      # 9 套动作各画什么、几帧、什么节奏
│   └── pack-spec.md            # 包结构、sheets.json、构建命令、质检清单
└── templates/
    └── sheets.json             # 切格声明模板
```

SKILL.md 开头的 `description` 很关键：当你说"给桌宠换个形象/我上传了概念图"
时，AI 靠这段话判断要不要启用这个技能。正文把流程固化成 5 步：

1. 检查环境（仓库、虚拟环境、u2net 模型目录）；
2. 以概念图为形象锚点，用**图生图**逐套生成青蓝底条图（每排≤3 格、
   长边≤4000、肢体四周留 8% 空白……这些全写在 animation-brief 里）；
3. 写 sheets.json；
4. 调 pack_build.py 构建；
5. 打开品红质检图逐帧验收，不合格只重做那一套。

### 一键导入是怎么回事？

技能本质上就是一个放在固定目录里的文件夹。豆包工作的用户技能目录在：

```
%LOCALAPPDATA%\DoubaoWork\...\workspace\.user_skills\
```

`app/skill_import.py` 做的事就是把随程序附带的技能目录**整个复制**过去
（`shutil.copytree(..., dirs_exist_ok=True)`）。所以右键菜单点
「制作新形象（导入生成技能）…」→ 复制技能 → 打开形象文件夹 →
把豆包工作窗口拉到最前面，你在新会话里上传概念图就能开工。

开发态技能源文件在仓库 `skills/` 目录；打包时 pet.spec 已把整个
`skills/` 打进去，所以 exe 用户也有这个技能可导入。

## 七、小作业（检验你看懂了）

1. **（动手）** 右键小龙 →「更换形象」→「打开形象文件夹」，
   看看这个文件夹在你电脑上的真实路径；开发态和打包版分别在哪里？
   （提示：搜代码里的 `data_dir()`。）
2. **（理解）** 朋友只给你一个只有 idle 和 happy 的角色包，为什么程序不会崩？
   播放 blink 时屏幕上是谁在眨眼？
3. **（动手）** 找一张任意角色的图片当"概念图"，在豆包工作里开新会话，
   说"用桌宠形象工坊给我做个新形象"，观察它是不是按 SKILL.md 的 5 步走。
4. **（思考）** 为什么质检图用品红底而不是白底？
   试着在 `pack_spec.md` 的质检清单里找到答案。
