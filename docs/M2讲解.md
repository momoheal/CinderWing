# M2 讲解：小龙是怎么知道"豆包工作的任务开始/结束了"的？

> 版本：v0.9.0（M2）　｜　对应代码：`app/task_source.py`、`app/main.py`
> 阅读对象：零基础的你。看完你能向朋友讲清楚：**一个网页里的任务状态，怎么变成桌面上小龙的一句话。**

---

## 一、先回顾：我们要解决什么问题

M0 我们搭了窗户（透明置顶窗口 + 托盘）。
M1 我们做了小龙的身体和表情（52 帧动画、点击、拖拽、睡觉、气泡外观）。

但那时小龙说的话是**假的**——`app/dev_sim.py` 像一个闹钟，按时间表
"演"出任务开始、进度 65%、任务完成。你双击 `启动宠物.bat` 正常启动时，
小龙其实什么都不知道。

**M2 的目标：让小龙读到豆包工作客户端里真实发生的 Agent 任务。**

你在豆包工作里让 Agent 干活（比如"帮我改这个游戏"），小龙要能：

1. 任务**开始**时说："任务开始：xxx"；
2. 任务**进行中**时，气泡里的进度条往前走；
3. 任务**需要你拍板**（授权/确认）时，红色气泡提示"需要你决策"；
4. 任务**完成/失败**时，明确说出来，小龙配开心或晕倒动作。

这正是 Codex Pets 的做法：**宠物是任务状态的"播报员"**。

---

## 二、最大的难点：豆包工作不发"通知"，数据藏在数据库里

普通软件有新消息会弹 Windows 通知（toast），我们只要听通知就行。
但侦察发现：**豆包工作不发系统通知**，界面还是加密的，没法直接读界面。

那任务数据存在哪？答案：**Chromium 内核的 IndexedDB**。

豆包工作是个 Electron 应用（可以理解成"一个专门的 Chrome 浏览器里
只跑一个网页"）。网页程序常用浏览器自带的小数据库 IndexedDB 存数据。
任务列表就存在本机这个文件夹里：

```
C:\Users\你的用户名\AppData\Local\DoubaoWork\User Data\Default\
  IndexedDB\chrome_doubaowork-chat_0.indexeddb.leveldb\
```

它是 **LevelDB** 格式（Google 发明的键值数据库，Chrome 存网页数据的标准格式），
旁边还有个 `.blob` 文件夹放大块数据。

> 白话：豆包工作把"任务清单"写在一个它自己的小本子上，本子锁在它的
> 抽屉里。我们不能直接翻它正在写的那一页（会打架），但可以**把整本本子
> 复印一份**，慢慢读复印件。

### 为什么要"复印"而不是直接读？

LevelDB 运行时会给文件加锁，而且它随时在写——你读到一半它写了下一笔，
就像撕书撕到一半，会读到残缺页（实测真的会：有一轮快照里任务标记
突然消失，下一秒又回来了，这叫**半写快照**）。

所以 `task_source.py` 每 3 秒做一次：

1. 把 `leveldb` 和 `.blob` 两个文件夹整个**复制**到临时目录
   `%TEMP%\geoharbour_pet_idb`；
2. 用第三方库 `ccl_chromium_reader` 打开**复印件**；
3. 读出任务清单。

复制过程中偶尔读到残缺页怎么办？**跳过这一轮，3 秒后再试**——
代码里所有读取都包在 `try/except` 里，出错只写一行日志，绝不崩溃。

## 三、数据在数据库里长什么样？（侦察成果）

这是 M2 最花时间的部分：真实字段没有文档，全靠抓包对照。
我写了个"侦察兵"脚本 `tools/_m2_watch.py`，每秒读一次数据库，
任务一出现/一变化就把完整内容 dump 成 JSON 存到
`tools/_m2work/dumps/`，再人工逐行读。

最终定位到的路径：

```
数据库 samantha-web  →  对象仓库 "store"
  →  键 default-chat-im-protocol-store
  →  值.state.mainTaskDataMap        ← 任务清单，按任务 UUID 索引
```

`mainTaskDataMap` 里每个任务是一大段 JSON，关键结论：

### 1. 怎么区分"真 Agent 任务"和"普通聊天"？

你在豆包工作里随便问一句话，也会产生一条临时记录，不能让小龙
把所有闲聊都当任务播报。

真任务的标记藏得很深：

```
requestQuery.syncTask.option.general_task_param   ← 有这个字段 = Agent 任务
```

（兜底：`syncTask.ext.is_general_task == "1"`。）
实测用一条普通聊天样本验证过：它没有这个字段，小龙不会理它。

### 2. 怎么判断任务到了哪一步？

顶层有个 `stage` 字段，**永远是 "sync"，没用**。真实状态在
`receivedMessages`（Agent 回给客户端的消息）的 `extra` 里：

| 信号 | 含义 |
|---|---|
| `receivedMessages[*].extra.ext.is_finish == "1"` | **本轮真正结束的唯一可靠信号**；它在完成后保留几分钟，随后记录会被重写、标记消失（所以 3 秒轮询要趁这个窗口抓到；启动时已存在的旧任务一律不回播） |
| `extra.ext.mode_downgrade_reason == "success"` | **不能**单独当终态：任务跑到一半它也是 success；只在 is_finish=1 的同一轮用于区分成功/失败 |
| `sentMessages[*].extra.final_status.message == "Success"` | **不能**当终态：实测任务刚发出时它就是 Success（表示"请求发送成功"） |
| `syncTask.ext.is_finish` | **无效**：所有任务（包括正在跑的）都是 "1"，是请求模板字段 |

> 踩坑记录：一开始以为 `extra.status == 4` 是"完成"，抓包发现任务
> **刚开始流式传输时它就是 4**；`sent.final_status=Success`、
> `mode_downgrade_reason=success`、`syncTask.ext.is_finish=1` 也都在
> 运行中就出现。逐个排除后，只剩 received 侧的 `ext.is_finish=="1"`
> 与"任务真正结束"严格对应。

### 3. 任务在干什么？看"内容块"

Agent 的回复被切成一个个 **content block（内容块）**，每个块有编号：

| block_type | 是什么 |
|---|---|
| 10000 | 正文文字 |
| 10040 | 思考过程 |
| 10091 | 计时条 |
| 10019 | 执行 shell 命令 / 文件操作 |
| 10024 | 通用工具调用（如查看后台任务） |
| 10083 | 电脑操作（computer use 代码） |
| 10025 | 联网搜索结果 |
| 10006 | 网页阅读（web.fetch） |
| 10010 | AI 生图工具结果 |
| 10068 | GUI 自动化工具（Wait/点击等） |
| 10084 | 富媒体排版容器（纯展示，不计工具动作） |

### 4. 没有进度百分比，怎么办？

数据库里**没有任何数字表示"完成了百分之多少"**。所以我们根据块的
出现顺序，合成一个只会往前走、不会倒退的**伪进度**：

```
任务刚出现               →  4%
出现思考块               → 18%
每多一个工具块 +7%       → 28%~82% 封顶
最后一块是收尾正文       → 90%
（运行中最高只到 96%）
is_finish=1              → 100%
```

这不是真实百分比，但符合你的直觉：思考→动手干活→写总结→完成，
进度条稳步前进，不会乱跳。

### 5. "需要你决策"（WAITING）——目前还没抓到样本

需要授权/确认时的特殊字段，在已抓到的任务里都没出现
（你的环境基本是自动放行的）。代码里先埋了两个安全的钩子：
`option.permission_interact` 不再是 `<Undefined>` 时判 WAITING；
遇到没见过的新块类型，自动写进 `assets/pet.log`
（M2 期间就是这样陆续发现了 10010/10068/10084 三种新块）。

> 踩坑：第一版还会在块的文字内容里搜 "permission" 等关键词，
> 结果一个已完成任务因为 shell 输出里包含 `local_permissions`
> （定位权限列表）被误判成"需要决策"。**正文文本不能当结构化
> 信号**，该启发式已删除。拿到真正的授权弹窗样本后再补判定。

## 四、代码结构：`DoubaoTaskSource` 这个"值班员"

`app/task_source.py` 里的 `DoubaoTaskSource` 类，可以想象成一个
每 3 秒巡视一次的值班员：

```
QTimer（3 秒）
   ↓
poll()
   ├─ 1. 复印数据库（_snapshot）
   ├─ 2. 读出任务清单（_read_tasks）
   └─ 3. 对每个真任务：
         _is_real_agent_task()  是 Agent 任务吗？
         _query_text()          任务名叫什么（你的原话）
         _extract()             判断状态 + 算伪进度
               ↓
         和"上次见到的样子"对比，决定要不要喊小龙：
           没见过的新任务  → bubble.notify("START", ...)
           进度涨了        → bubble.update_progress(...)（只刷新进度条）
           要决策了        → bubble.notify("WAITING", ...)
           is_finish       → bubble.notify("DONE"/"FAIL", ...)
```

### 三个防抖设计（都是实测逼出来的）

1. **启动不回播历史**：第一次扫描只登记、不说话。否则你每次开机，
   小龙都会把数据库里躺着的旧任务挨个报一遍"任务完成"。
2. **状态不许倒退**：任务明明在跑，半写快照突然让它"变回刚创建"，
   这种轮次直接忽略。
3. **任务消失要连续 3 轮不见才算数**；已经报过完成的任务记录
   再保留 20 轮，防止它在数据库里"回闪"导致重复播报。

### 接到主程序

`app/main.py` 里：

- 双击 `启动宠物.bat`（普通模式）→ 启动 `DoubaoTaskSource`，读真实数据；
- `启动宠物.bat --sim`（模拟模式）→ 启动 `dev_sim` 演假任务，
  方便没有真实任务时调试气泡。

气泡（`bubble.py`）状态一变，会发信号给 `pet_window.py`：
说话中→小龙循环 `talk` 说话动作；完成→`happy` 欢呼；失败→晕倒。

## 五、怎么自己验证 M2？

1. 双击 `启动宠物.bat`（**不要**带 `--sim`）；
2. 在豆包工作里发起一个真正的 Agent 任务（会执行命令/改文件的那种）；
3. 观察小龙：
   - 几秒内弹出"任务开始：……"，小龙进入说话动作；
   - 进度条随任务推进上涨；
   - 完成时弹绿色"任务完成"，小龙欢呼；
   - 气泡停留期间点一下气泡，能展开多任务面板，看到所有在跑的任务。
4. 出问题看日志：`assets/pet.log`（搜索 `[task_source]`）。

侦察兵脚本（想看原始数据变化时用）：

```bat
cmd /c tools\_start_watch.bat
```

它会每秒读一次数据库，输出到 `tools/_m2_watch.log`，
原始 JSON 落在 `tools\_m2work\dumps\`。

## 六、小作业（检验你理解了没有）

1. （概念）为什么代码要先**复制** IndexedDB 再读，而不是直接读原文件？
2. （概念）为什么不能用 `extra.status == 4` 判断任务完成？真正的
   终态信号是哪个字段？
3. （动手）用记事本打开 `app/task_source.py`，找到伪进度那段
   （搜索 `28.0 + n_tool * 7.0`），把工具块每次加的百分比从 7 改成 10，
   保存后重启宠物，发起一个任务，观察进度条变化有什么不同。
   （改完记得改回 7。）
4. （观察）下次你在豆包工作遇到"需要授权/确认"的弹窗时，
   打开 `assets/pet.log` 看有没有 `unknown block_type=` 的新记录——
   那就是我们等待的 WAITING 真实样本，把它发给我即可完成最后一块拼图。
